# Dasar Teori

Proses adalah program yang sedang dieksekusi oleh sistem operasi. Dalam sistem operasi, proses dapat dijalankan secara sekuensial maupun konkuren. Proses sekuensial dijalankan secara berurutan sehingga proses berikutnya baru dapat berjalan setelah proses sebelumnya selesai. Sedangkan proses konkuren memungkinkan beberapa proses berjalan secara bersamaan atau bergantian sesuai dengan mekanisme penjadwalan (scheduler) yang digunakan oleh sistem operasi.

Xinu merupakan sistem operasi pendidikan yang menyediakan berbagai mekanisme manajemen proses, seperti pembuatan proses baru, penghapusan proses, penjadwalan CPU, sinkronisasi, dan komunikasi antar proses. Melalui praktikum ini, mahasiswa dapat memahami perbedaan antara proses sekuensial dan konkuren serta mengamati fenomena race condition pada proses yang mengakses data bersama.

# Jurnal 1

## Soal

Carilah pada source code Xinu yang memberi batasan mengenai banyaknya proses yang bisa dibuat! Berapa maksimal proses dalam Xinu? Ubah menjadi maksimal 150 proses!

## Jawaban

Batas maksimal jumlah proses pada Xinu ditentukan oleh konstanta `NPROC` yang terdapat pada file:

```c
include/conf.h
```

Nilai awal:

```c
#define NPROC 100
```

Kemudian diubah menjadi:

```c
#define NPROC 150
```

Sehingga jumlah maksimum proses yang dapat dibuat dalam sistem Xinu berubah dari 100 proses menjadi 150 proses.

# Jurnal 2

## Soal

Jalankan kode sekuensial!

## Source Code

```c
#include <xinu.h>

void prosesA(void)
{
    int i;

    for(i=1; i<=5; i++){
        kprintf("Proses A : %d\n", i);
    }
}

void prosesB(void)
{
    int i;

    for(i=1; i<=5; i++){
        kprintf("Proses B : %d\n", i);
    }
}

process main(void)
{
    kprintf("\n=== Proses Sekuensial ===\n");

    prosesA();
    prosesB();

    return OK;
}
```

## Hasil

```text
=== Proses Sekuensial ===

Proses A : 1
Proses A : 2
Proses A : 3
Proses A : 4
Proses A : 5
Proses B : 1
Proses B : 2
Proses B : 3
Proses B : 4
Proses B : 5
```

## Analisis

Pada program sekuensial, fungsi `prosesA()` dijalankan terlebih dahulu hingga selesai sebelum `prosesB()` dijalankan. Karena kedua fungsi dipanggil secara langsung tanpa menggunakan mekanisme pembuatan proses baru, urutan output selalu sama dan dapat diprediksi.

# Jurnal 3

## Soal

Jalankan kode konkuren!

## Source Code

```c
#include <xinu.h>

process prosesA(void)
{
    int i;

    for(i=1; i<=10; i++){
        kprintf("Proses A : %d\n", i);
    }

    return OK;
}

process prosesB(void)
{
    int i;

    for(i=1; i<=10; i++){
        kprintf("Proses B : %d\n", i);
    }

    return OK;
}

process main(void)
{
    kprintf("\n=== Proses Konkuren ===\n");

    resume(create(prosesA, 1024, 20, "prosesA", 0));
    resume(create(prosesB, 1024, 20, "prosesB", 0));

    return OK;
}
```

## Hasil

Contoh output:

```text
=== Proses Konkuren ===

Proses A : 1
Proses B : 1
Proses A : 2
Proses B : 2
Proses A : 3
Proses B : 3
...
```

## Analisis

Pada program konkuren, proses dibuat menggunakan fungsi `create()` dan dijalankan menggunakan `resume()`. Kedua proses dijadwalkan oleh scheduler sehingga urutan output dapat berbeda-beda pada setiap eksekusi. Hal ini menunjukkan bahwa proses dapat berjalan secara bersamaan atau bergantian sesuai kebijakan penjadwalan sistem operasi.

# Jurnal 4

## Soal

Buatlah proses produser dan konsumer menggunakan variabel global bersama.

## Source Code

### producerconsumer.c

```c
#include <xinu.h>

int32 n = 0;

process produser(void)
{
    int32 i;

    for(i=1; i<=1000; i++){
        n++;
    }

    return OK;
}

process konsumer(void)
{
    int32 i;

    for(i=1; i<=1000; i++){
        kprintf("Nilai dari n adalah %d\n", n);
    }

    return OK;
}
```

### main.c

```c
#include <xinu.h>

extern int32 n;

process produser(void);
process konsumer(void);

process main(void)
{
    kprintf("\n=== Produser Konsumer ===\n");

    resume(create(produser, 1024, 20, "produser", 0));
    resume(create(konsumer, 1024, 20, "konsumer", 0));

    return OK;
}
```

## Hasil

Contoh output:

```text
Nilai dari n adalah 0
Nilai dari n adalah 0
Nilai dari n adalah 15
Nilai dari n adalah 48
Nilai dari n adalah 103
Nilai dari n adalah 500
Nilai dari n adalah 1000
```

## Analisis

Hasil program tidak sesuai dengan intuisi awal karena terjadi race condition. Variabel global `n` diakses secara bersamaan oleh proses produser dan konsumer tanpa mekanisme sinkronisasi. Scheduler dapat memberikan CPU kepada salah satu proses kapan saja sehingga konsumer dapat membaca nilai `n` sebelum produser selesai melakukan increment. Akibatnya output yang dihasilkan menjadi tidak deterministik dan dapat berbeda pada setiap eksekusi program.

# Kesimpulan

Pada praktikum ini telah dipelajari konsep proses sekuensial dan proses konkuren pada sistem operasi Xinu. Proses sekuensial dieksekusi secara berurutan sehingga output dapat diprediksi. Sebaliknya, proses konkuren dijalankan oleh scheduler sehingga urutan output dapat berubah-ubah. Selain itu, percobaan produser dan konsumer menunjukkan adanya race condition ketika dua proses mengakses variabel global yang sama tanpa mekanisme sinkronisasi. Oleh karena itu, sinkronisasi diperlukan untuk menjaga konsistensi data pada sistem multiproses.
